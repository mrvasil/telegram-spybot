# Работа с Spybot

## Назначение

Личный Telegram-архив для одного владельца. Приоритет: сохранность доставленных данных, затем удобство интерфейса. Начните с README.md, PROGRESS.md и docs/DESIGN.md. Текущее поведение определяется исходниками и тестами; записи о прошлых проверках не доказывают состояние работающего сервера.

## Структура

- `archive.py`, `schema.py`: транзакции, версии, inbox, FTS, задания.
- `runtime.py`, `telegram.py`: приём обновлений и Bot API.
- `media.py`, `crypto.py`: сохранение, проверка и шифрование файлов.
- `operations.py`: backup, restore, экспорт и стирание.
- `ui.py`, `render.py`: авторизация владельца, карточки и уведомления.
- `config.py`, `cli.py`: настройки и запуск.

Все пути модулей относятся к `src/spybot/`.

## Обязательные свойства

1. Inbox и offset фиксируются вместе; Telegram не подтверждается до успешной записи.
2. Правки собственных сообщений владельца исключаются до записи inbox, включая отредактированный контекст ответов; их содержимое и файловые задания не сохраняются. Для остальных сообщений неизвестные поля сохраняются. Правки собеседников добавляют версии, удаление в Telegram не стирает локальную копию.
3. Полученные файловые ссылки ставятся в постоянную очередь независимо от настроек уведомлений.
4. Завершение задания проверяет аренду и номер попытки. Устаревший worker не должен менять результат новой попытки.
5. Локальное стирание согласуется с чтением, экспортом и отправкой через общий lock. Нельзя отправлять устаревший снимок стёртых данных.
6. При неопределённом исходе отправки нельзя автоматически отправлять повторно. Возврат от native media к document допустим после явного отказа API.
7. Доступ к UI и выдаче файлов имеет только владелец в личном чате. Защищённые вложения выдаются с `protect_content`.
8. Ключ хранится вне каталога данных. Не создавайте открытые временные копии переписки и файлов.

## Интерфейс

Русский язык, компактные карточки, безопасный HTML. Правки показывайте один раз как «Было / Стало». Фото и видео выдавайте своим типом. При удалении доставляйте все уникальные основные вложения автоматически через отдельные задания; не заменяйте их кнопкой просмотра. Ожидание загрузки одного файла не блокирует остальные. Не показывайте JSON, file_id, трассировки и технический diff в обычных карточках. Полные поля доступны в экспорте. Пользовательский текст экранируется; лимиты Telegram учитываются в UTF-16.

## Проверки

```bash
uv sync --frozen
uv run pytest -q
uv run ruff check src tests
uv run ruff format --check src tests
uv run mypy src/spybot
git diff --check
```

Добавляйте регрессионные тесты для потери данных, гонок, авторизации и ошибок API. Используйте временную SQLCipher-базу и локальный HTTP-двойник. Для правок только документации проверяйте ссылки, команды и отсутствие секретов; полный runtime-прогон без причины не нужен.

## Границы работы

Не выводите `.env`, ключи, переписку и реальные API payloads в терминал, логи, коммиты или задачи GitHub. Не используйте настоящие токены в тестах. Запуск реального бота, отправка сообщений и изменения на сервере требуют действующего поручения пользователя; разрешение на локальную правку само по себе этого не даёт.

Перед согласованным обновлением проверьте место на диске и создайте backup. Сохраните прежний образ для отката; не заменяйте ключ и каталог данных. В SSH-скриптах закрывайте stdin у Docker run/exec, чтобы контейнер не поглотил оставшиеся команды скрипта.

Не обещайте сохранение файлов, которые Telegram не предоставил. Не добавляйте миграцию, многопользовательский режим или Mini App без отдельной задачи. При изменении поведения обновляйте CHANGELOG.md и нужный раздел руководства; актуальное состояние ведите в PROGRESS.md.
