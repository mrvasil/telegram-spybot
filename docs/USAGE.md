# Руководство пользователя

Личный зашифрованный архив сообщений Telegram. Сохраняет полученные сообщения, версии правок собеседников, события удаления и доступные вложения. Управляется одним владельцем через Telegram.

## Как сохраняются данные

- Правки собственных сообщений владельца не сохраняются и не вызывают уведомлений. Фильтр применяется до записи JSON и к отредактированным сообщениям владельца в контексте ответов. Исходные исходящие сообщения сохраняются; старые записи автоматически не удаляются.
- Остальной исходный JSON целиком записывается в SQLCipher **до подтверждения получения Telegram**. Неизвестные поля и типы сообщений не отбрасываются.
- Тексты, подписи, entities, пересылки, геоданные, альбомы, структурированные сообщения и контекст ответов сохраняются вместе с версиями.
- Входящие и исходящие сообщения, переданные Business API, сохраняются. Ответ владельца может дополнительно сохранить ранее неизвестное сообщение из `reply_to_message`.
- Все обнаруженные `file_id` ставятся в постоянную очередь. Основные файлы скачиваются раньше миниатюр; старые задания постепенно повышают приоритет.
- Telegram-удаление помечает запись удалённой, но не уничтожает локальные версии или файлы.
- Уведомления и скачивание работают независимо от приёма. Отключение уведомлений не отключает архивирование.
- По умолчанию архив хранится **без ограничения срока**. При нехватке диска данные не вытесняются автоматически.
- База, FTS-индекс, вложения, временные экспорты и backup зашифрованы. Ключ хранится отдельно. Логи не содержат текстов переписки и токена.

Бот сохраняет то, что Telegram ему передал. Он не получает произвольную старую историю, секретные чаты, скрытую личность отправителя или байты недоступного одноразового файла. Спойлеры и неизвестные поля сохраняются, если присутствуют в update. Событие удаления само по себе не содержит удалённого текста. После простоя больше 24 часов Telegram может уже не иметь недоставленных updates.

## Быстрый запуск

Требуются Python 3.13 и [uv](https://docs.astral.sh/uv/getting-started/installation/). Docker используется по желанию.

```bash
uv sync --frozen
cp .env.example .env
chmod 600 .env
mkdir -p data
chmod 700 data
uv run spybot init --key-file "$HOME/.config/telegram-spybot/archive.key"
```

Заполните `.env`:

- `TOKEN` — токен своего бота из BotFather.
- `USER_ID` — числовой Telegram ID единственного владельца.
- `ARCHIVE_KEY_FILE` — **абсолютный путь** к созданному ключу, вне каталога `data`.
- `TIMEZONE` — часовой пояс отображения и тихих часов.

Сохраните отдельную резервную копию ключа. Новый ключ не сможет открыть существующий архив; `init` намеренно не перезаписывает ключи.

```bash
uv run spybot run
```

В Telegram:

1. Включите Secretary Mode для бота в BotFather (раньше назывался Business Mode).
2. Откройте личный чат с ботом и отправьте `/start`.
3. Подключите его к своему аккаунту в настройках Telegram и выберите чаты.
4. Проверьте `/status` и появление тестового сообщения в `/archive`.

По текущей документации подключение бизнес-бота не требует Premium. На аккаунт можно подключить только одного такого бота. Архиватор не пишет от вашего имени и не отмечает переписку прочитанной; права управления подарками, Stars и профилем ему не нужны.

Встроенный способ приёма — long polling. Если у токена уже установлен webhook, запуск остановится: переключение должно быть явным, без удаления pending updates. Одновременно должен работать только один экземпляр с этим токеном и каталогом данных.

## Команды

Основная навигация доступна кнопками.

| Команда | Назначение |
| --- | --- |
| `/status` | Состояние архива, очередей, файлов и backup |
| `/chats`, `/archive`, `/deleted` | Чаты, архив и удалённые сообщения |
| `/chat ID` | Архив выбранного чата |
| `/message ID` или `/ID` | Версии записи по **внутреннему ID архива** |
| `/search слова` | Поиск по всем сохранённым версиям |
| `/search_chat ID слова` | Поиск в одном чате |
| `/settings` | Настройки уведомлений |
| `/mute [ID]`, `/unmute [ID]` | Отключить/включить уведомления; архив продолжает работать |
| `/ignore N` | Не уведомлять о мелких текстовых правках; версии сохраняются |
| `/quiet 23:00-08:00`, `/quiet off` | Тихие часы |
| `/digest 10`, `/digest 0` | Сводки с интервалом в минутах либо немедленные уведомления |
| `/bookmark ID`, `/unbookmark ID`, `/bookmarks` | Закладки |
| `/export [ID_чата]`, `/export_media [ID_чата]` | ZIP с JSONL и HTML; второй вариант включает файлы |
| `/backup` | Создать зашифрованную резервную копию на сервере |
| `/retry` | Повторить известные неудачные операции |
| `/retry_uncertain` | Явно повторить неоднозначные отправки; возможны дубликаты |
| `/retention N` | Срок хранения в днях; `0` — без автоматического удаления |
| `/delete ID` | Удалить запись из локального архива после подтверждения |

После изменения тихих часов/сводок уже отложенные уведомления могут ждать прежнего времени очереди. Новая политика проверяется перед отправкой.

Фото, видео, голосовые и другие поддерживаемые вложения открываются прямо в Telegram. При удалении все уникальные основные вложения сохранённых версий отправляются автоматически, каждое отдельным заданием. Фото приходит фотографией, документ — файлом; миниатюры и повторяющиеся копии не засоряют чат. Ещё скачивающийся файл отправляется после загрузки без нажатия кнопок. При недоступности оригинала фото используется сохранённый меньший размер, если он есть. Для этих доставок тихие часы и сводки не применяются; отключение уведомлений по-прежнему действует. При отклонении формата Telegram файл отправляется документом; оригинальные байты остаются в архиве и экспорте. Защищённые сохранённые файлы доступны только владельцу с запретом пересылки (`protect_content`). Смена/удаление username не влияет на идентификацию. Неизвестный автор удаления не подменяется именем собеседника.

## Docker

Сначала создайте `.env`, ключ и каталог `data` по инструкции выше. Установите `RUN_UID` и `RUN_GID` в `.env` равными результатам `id -u` и `id -g`. `DATA_DIR` — путь на хосте; `ARCHIVE_KEY_FILE` — абсолютный путь на хосте.

```bash
docker compose up -d --build
docker compose logs --tail=100 -f
docker compose ps
```

Контейнер работает без root, с read-only root filesystem и отдельными bind mounts для ключа и данных. Права: `.env` и ключ — `600`, каталог данных — `700`. Автоматического удаления томов, переустановки Docker и сброса базы нет.

Обновление:

```bash
docker compose build
docker compose up -d
```

Проверьте `/status` после обновления. Исходники находятся в образе, данные — отдельно. Остановка: `docker compose down` (bind mounts остаются).

## Файлы большого размера

Облачный Bot API ограничивает `getFile` файлами до 20 МБ. При таком отказе текст, метаданные и `file_id` сохраняются, а файл получает понятный статус; `/retry` позволяет повторить загрузку после смены профиля.

Для больших файлов можно отдельно развернуть [официальный Local Bot API Server](https://core.telegram.org/bots/api#using-a-local-bot-api-server). Приложение поддерживает `BOT_API_URL` и, для серверного режима `--local`, `LOCAL_BOT_API_FILES_DIR` с доступным только для чтения каталогом файлов по тому же абсолютному пути. Переход между серверами требует официальной процедуры Telegram (`logOut` и согласованного переключения). В базовую установку этот отдельный сервер не входит.

`MAX_FILE_BYTES` ограничивает локальное скачивание, `MIN_FREE_BYTES` оставляет запас места. Переполненный диск требует вмешательства владельца; архиватор не может сохранять новые данные без места.

## Резервные копии и экспорт

Автоматический backup: каждые 24 часа, последние 7 копий. Настройки: `BACKUP_HOURS`, `BACKUP_KEEP`; `BACKUP_HOURS=0` отключает расписание. Копии на том же диске защищают от части ошибок, но не от потери диска: переносите зашифрованные `.sba` на отдельный носитель.

Offline-команды выполняются при остановленном боте; для работающего используйте `/backup` и `/export`:

```bash
uv run spybot status
uv run spybot backup
uv run spybot export --include-media
uv run spybot restore data/backups/ИМЯ.sba restored-data
```

Восстановление допускается только в новый каталог с тем же ключом. Проверяются целостность контейнера, манифест, файлы и количества записей. Старый backup отражает состояние на момент создания: он может содержать записи, которые были удалены позднее. Уже отправленные в Telegram копии тоже не исчезают при локальном `/delete`.

Локальный экспорт хранится зашифрованным. Для явного получения обычного ZIP:

```bash
uv run spybot decrypt data/exports/ИМЯ.sba archive.zip
```

`archive.zip` содержит открытые данные — храните его соответственно. Telegram-экспорт расшифровывается потоком при отправке владельцу; временного открытого файла на сервере нет. Если ZIP превышает лимит отправки, сузьте экспорт до одного чата или воспользуйтесь локальной командой. Автоматического деления больших ZIP на тома в этой версии нет.

## Проверки и структура

```bash
uv run pytest -q
uv run ruff check src tests
uv run ruff format --check src tests
uv run mypy src/spybot
```

`src/spybot`: архив и схема, приём Telegram, загрузка файлов, шифрование, UI, обслуживание и CLI. `tests`: реальные SQLCipher/FTS и файлы, синтетические Telegram updates/HTTP, сбои, рестарты и гонки.
