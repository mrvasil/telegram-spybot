# Устройство архива

Один владелец, один процесс приёма, отдельные фоновые задачи. Python 3.13, raw aiohttp Bot API, aiosqlite + SQLCipher, FTS5. Переход на сырой API вместо SDK сохраняет неизвестные поля и снимает зависимость сохранности от отставания SDK от схемы Telegram.

1. `getUpdates` возвращает полный JSON. По явному правилу владельца содержимое его правок исключается до записи, включая отредактированные контекстные сообщения; сохраняется только служебная идентичность события. Inbox и следующий offset сохраняются одной транзакцией WAL/FULL. Только затем отправляется следующий offset Telegram.
2. Проверяется владелец business connection. Известное отключённое подключение не мешает сохранить уже доставленные события. Неизвестное подключение разрешается через API с повторными попытками.
3. Применение update атомарно создаёт сообщения, версии, контекст, события удаления, файловые задания и уведомления. Версии не перезаписывают историю. Повторы дедуплицируются по update ID.
4. Независимые загрузчики получают все обнаруженные `file_id`. Основные файлы приоритетнее превью; приоритет стареет, чтобы вспомогательные файлы тоже обслуживались.
5. У каждой задачи есть аренда и номер попытки. Обновление состояния медиа и завершение задания проверяют владение атомарно. Отложенная старая попытка не может затереть новую.
6. Отправки имеют outbox и ограничитель. `429` вводит общий cooldown. При неопределённом результате отправки автоматического повтора нет: Telegram не предоставляет универсальный ключ идемпотентности отправок.
7. Ручное стирание редактирует только связанные фрагменты inbox, сохраняя чужие для этой операции pending events; аннулирует производные уведомления и экспорты. Новая доставка не должна воскресить явно стёртую запись.

База и её индекс зашифрованы SQLCipher. Файлы — последовательность AES-256-GCM chunks с индивидуальным HKDF salt, порядком chunks в AAD и аутентифицированным EOF. Ключ 32 байта хранится в отдельном файле `600`. SQLCipher temporary store в памяти; незашифрованных временных вложений нет. Это серверное шифрование при хранении, не E2EE: процесс сервера читает данные для поиска и выдачи владельцу.

Backup: согласованный зашифрованный snapshot базы + связанные зашифрованные файлы + манифест, упакованные в зашифрованный контейнер. Публикация только атомарным rename после завершения. Restore проверяет весь контейнер до записи и не перезаписывает существующий каталог.

Ограничения: Telegram не доставляет всё содержимое аккаунта; после длительного простоя возможен необратимый пробел; доступность файла определяется Telegram; переполненный диск требует действий владельца. В этой версии нет Mini App, многопользовательского доступа или миграции старой базы.

При удалении медиа родительское уведомление атомарно заменяется отдельными дедуплицированными заданиями файлов. Каждый файл имеет собственную аренду и результат; ожидание загрузки и сбой одного вложения не повторяют успешно отправленные соседние файлы.
