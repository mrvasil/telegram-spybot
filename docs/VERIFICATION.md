## Что покрывают тесты

- Отдельный процесс бота работает против локального HTTP-двойника Bot API: сообщение → правка → удаление, скачивание вложений, неизвестные JSON-поля, штатная остановка.
- Принудительное завершение после записи inbox и восстановление после перезапуска; ошибка диска не продвигает offset.
- Сохранение версий, контекстных ответов, исходных updates и метаданных недоступных файлов. Удаление в Telegram не стирает локальный архив.
- SQLCipher и неверный ключ; проверка целостности зашифрованных файлов; backup, восстановление и экспорт.
- Постоянные очереди, повторные попытки, устаревшие аренды заданий, гонки скачивания и локального стирания, ошибки отправки, права владельца.
- Локальное стирание сериализовано с формированием истории/списка вложений; удалённый вложенный контекст не отправляется из устаревшего снимка. Автоматическое удаление по сроку инвалидирует ранее созданные экспорты, включая экспорты только текстовых записей. Три завершающих регрессионных теста падают на предыдущем коде и проходят после исправления.

## Границы проверки

Реальные Telegram Business/Secretary updates, подключение владельца, реальные ограничения облачной/локальной Bot API и отправки больших файлов не проверялись. Не проводились 72-часовой непрерывный прогон, нагрузочное испытание на миллионе сообщений и физическое отключение питания. Локальный HTTP-двойник не заменяет проверку подключения в Telegram.

После аварийного завершения могут оставаться зашифрованные временные файлы; автоматическая очистка всех таких остатков не реализована. Старые резервные копии могут содержать позже стёртые записи; уже отправленные в Telegram копии не отзываются.

Сохранность зависит от доступности диска, ключа и доставки Telegram. Нельзя восстановить содержание, которое Telegram не передал, или гарантировать скачивание уже недоступного файла. По умолчанию срок хранения не ограничен; автоматическое удаление включается только явно.
